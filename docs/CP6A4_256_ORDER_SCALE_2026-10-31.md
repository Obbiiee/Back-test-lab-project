# CP6A-4 — QA-v3 256-order scale gate

**Result: PASS for the bounded QA persistence and recovery gate.** This is an authored fixture test, not a market backtest, production qualification, or financial performance claim.

## Scope and invariants

- Started from accepted integration commit `e1ef7af68194d1cd7f512ac1f096fd6261335d84`, branch `codex/beta-integration-20261028`.
- Compared the legacy PostgreSQL format with opt-in QA-v3 using identical commands in separate private PostgreSQL databases and one continuous Session per database.
- Used the existing `QA_ORDER_RETENTION_V2` isolated-QA policy: 512 cumulative retained records, 128 active records. Production/default policy and authorities were not changed.
- Exercised 256 pending orders across LONG/SHORT LIMIT/STOP, then cancelled each before it could trigger. This is a completed-order-history storage workload: **0 fills, $0 realized P&L**. It does not test SL/TP execution.
- The fixture revealed one authored quote group. It is not the canonical XAUUSD 2024 dataset.

All 256 cancelled orders remained in the reconstructed state; active-order count was zero. Per-command full-result SHA-256 values and final logical state were identical between legacy and QA-v3. Balance remained `10000`, realized gross remained `0`.

- Default-policy worker process-kill regression: PASS.

## Storage and performance

| Measure | Legacy | QA-v3 |
|---|---:|---:|
| PostgreSQL database before workload | 9,296,919 B | 9,362,455 B |
| PostgreSQL database after workload | 17,005,591 B | 13,360,151 B |
| Database growth | 7,708,672 B | 3,997,696 B |
| Combined command-receipt and checkpoint payloads | 59,210,540 B | 1,889,816 B |
| WAL LSN growth | 9,409,776 B | 4,518,600 B |
| Median apply latency | 0.284 s | 1.010 s |
| P95 apply latency | 0.526 s | 2.793 s |

QA-v3 reduced database growth by **3,710,976 B (48.14%)** and combined receipt/checkpoint payloads by **96.81%**. Allocated `pg_wal` remained 33,554,432 B for both measurements; it is shared cluster allocation, not per-Session savings. The QA-v3 apply median was 3.56× the legacy median and P95 was 5.31×; storage savings therefore came with materially slower command processing at this scale.

The implementation reconstructs the complete delta history on durable reads. That is the measured follow-up bottleneck to review before increasing this workload further; no optimization or larger-order run was started here.

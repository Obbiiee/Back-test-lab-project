### Cross-phase quality model

**Hard constraints:** Security + Correctness.  
**Optimization priorities:** Lightweight → Efficient → Measured → Scalable.

Every authorized phase must apply the relevant risk-proportional gates: authorization/input security, deterministic correctness, no-look-ahead for temporal behavior, regression tests, performance measurement when performance is affected or claimed, build/lint/static checks, diff review, and the repository workflow checkpoint.

### Research-integrity foundations

The architecture must converge on:
- time-bounded market/news views so temporal consumers cannot casually read future observations;
- truncation-invariance tests for temporal features where applicable;
- Replay/Execution → canonical Event/Trade Log → Research Compute separation;
- a versioned/pluggable minimum execution model before advanced research claims, including explicit candle ambiguity, spread/cost/slippage assumptions as applicable;
- Experiment Passport content hashes for canonical dataset, strategy and protocol definitions plus engine/calculator/execution semantics and RNG provenance;
- append-only trial/strategy lineage sufficient to disclose prior exploration and support later hypothesis-family/multiple-testing analysis;
- explicit replay/backtest state transitions so chart/replay/trading/journal state cannot silently diverge.

Trial count is provenance, not an automatic statistical correction. Bonferroni, BH-FDR, DSR or other methods may be used only when appropriate to the defined inferential question and hypothesis family.

### Market-data rights gate

Before Phase 23 becomes a production cloud market-data service, verify applicable acquisition, storage, display/redistribution, commercial-use, retention and derived-data rights. Technical availability does not imply redistribution rights.

#### Phase 14.5 final implementation scope

Human decisions finalize the proposal below, not implementation authorization. The chat planning report elaborates tests/file impact. Preserve the execution-order decision above. The new research thesis and architecture blueprint are strategic references, not replacement authorities; their future Next.js/API/cloud/entitlement targets do not change the local React/Vite baseline or this scope.

**Domain and data:** dedicated `frontend/src/news/`; provider-neutral canonical UTF-8 JSON import version 1. One envelope owns schemaVersion, datasetId, version, provenance/license declaration, explicit scoped coverage intervals, event definitions and occurrences. Test fixtures are synthetic and labeled; do not bundle third-party historical datasets. Ten-year architecture capacity is required, ten years of real news acquisition is not. Provider adapters/CSV are SHOULD, automated ingestion/cloud DEFER.

**Identity:** eventTypeId identifies a recurring series; occurrenceId identifies a particular period/release stage. Definitions distinguish headline/core, MoM/YoY and FOMC statement/conference/minutes. Preserve source event names. IDs are opaque and stable across schedule changes; UTC timestamp alone is not identity. Duplicate IDs/versions or conflicting definitions reject import, not silent deduplication.

**Temporal model:** immutable versioned field facts contain value, availableAtUtc (nullable), evidence reference and source timestamp/timezone/precision. Include schedule/status, event display metadata, currency/category, impact, previous, forecast, actual and release-time facts. Null value with known availability means explicitly unavailable/cancelled; missing availability means unknown. Numeric facts also retain raw text, unit and reference period. Revised previous values differ from original previous values. RetrievedAt alone is never availability evidence. Logical identity/definition metadata is not exposed to replay unless backed by eligible facts.

**Strict query:** at raw M1 replay endpoint T select only facts with proven availableAtUtc <= T; unknown availability is hidden. Actual/release revisions additionally require proven release time <= T. Date-only availability conservatively becomes the next source-local midnight and is labeled coarse; date-only event time is list-only. Never expose full raw occurrences to strict UI/marker/navigation/context. Future schedule/currency/category/impact revisions cannot change current filters, target selection or context. Retrospective mode is an explicit read-only News research view with label and separate query/cache; it cannot drive replay navigation, strict markers or account writes.

**Time normalization:** imports accept ISO timestamp with explicit offset, optionally IANA zone for consistency checks; reject offset-free timestamps, invalid dates, missing precision, zone/offset contradictions or ambiguous local-only times. No local timezone inference. Source timezone/source time are retained. UTC seconds may retain subseconds; no truncation to candle timestamps. Display timezone never changes canonical data. Unsupported timezone conversion is an explicit error, never a guessed fallback.

**Coverage:** half-open UTC intervals declare currency/category scope and complete/partial/unknown status with provenance; implicit gaps are unknown. Only within asserted complete scope and without matching events may UI say no matching events. Partial/outside coverage must show uncertainty; filtered absence is not all-news absence. Coverage is a dataset quality declaration, not hidden historical release information.

**Persistence:** separate native IndexedDB news namespace, schema version 1, immutable dataset payloads plus active dataset reference. Canonical serialization sorts keys, definitions, IDs and fact versions before SHA-256; exclude the hash field itself. Store source-byte hash separately. Validate/normalize/hash/index before writing; one transaction writes payload and swaps active reference, preserving previous active dataset for recovery. Exact hash reimport is idempotent; reused datasetId/version with different hash rejects. Quota/blocked/abort errors retain last valid state, display error and do not claim success. Reload verifies schema/hash/invariants and rebuilds indexes; corrupt/future records remain preserved, never overwritten automatically; explicit restore previous/reimport is offered. Origin-local storage is not durable backup or cross-device sync. Filter/window preferences use a separate validated news preference record; ephemeral selection/navigation does not persist.

**Filters/UI:** functional existing News button/panel; initial currency USD, impact High, all categories. All/other currencies/other impacts/unknown are selectable; derived filters never delete data. Unknown facts do not qualify as known currency/impact. Persist news preferences only; no final visual redesign. Strict details display evidence/quality and hidden-field reasons.

**Markers:** a separate official Series Primitive adapter owns rendering/lifecycle, not the trading marker plugin. Receives only sanitized eligible events and revealed candle times. Anchor to containing timeframe bucket only when supported by revealed market coverage; no arbitrary floor-to-distant-candle across gaps. Events lacking an anchor stay in panel with unmapped status. Cluster shared bucket/coordinate with deterministic IDs; actual timestamp stays canonical. Zoom/pan/resize/timeframe/prepend update projection; no autoscale contribution or chart replacement. Cursor-only selection respects drawings/RiskReward and price-pane bounds. Detach/unsubscribe before chart removal; remount recreates no duplicate owners.

**Navigation:** stable timestamp groups; Next > cursor, Previous < cursor, equal-time releases selectable within group. Eligible targets derive from strict facts/filters known at navigation start. Previous/revealed selection moves viewport only, never rewinds account. Unrevealed Next pauses playback and uses existing step(+1), one outstanding step, waiting for committed revision and canonical trading settlement acknowledgement before the next; never writes replay index or starts/resets a session. Stop at first raw endpoint >= target (timeframe overshoot explicit); use normal chunk extension when required. Cancel stops future requests and preserves completed steps. Pause/timeframe/filter/dataset/session changes cancel the run. Out-of-market-range events cannot navigate; nearest candle is not silently substituted. Disable conflicting controls during an active run. If settlement ordering/equivalence cannot be proven without changing protected replay semantics, STOP/report blocker, do not rewrite replay.

**Windows:** versioned config with A>=B>=0, D>=C>=0, A,D>0; pre [-A,-B), during [-B,C), post [C,D). Initial preset A=D=3600, B=0, C=60 seconds: 60 minutes before, first minute at release, remaining time until +60 minutes. The one-minute during interval reflects current M1 resolution, not universal news-trading science. UI exposes before/after minutes and during lead/lag seconds; boundaries/exclusions are visible. Config content hash/version identifies results. Zero-width during is permitted and labeled empty.

**Research/Phase 14:** derived-only entry/each-exit context with signed delta = tradeTime-eventTime, all eligible matches, window class and nearest-within-window convenience (absolute delta, timestamp, ID tie-break). Do not label a global nearest outside configured windows. Strict associations evaluate information as-of each entry/exit timestamp, with current cursor as upper bound; retrospective recomputation is separately labeled in News panel. Revisions learned later do not rewrite what was known at trade decision time. Dataset hash/query version/window hash identify context. Missing legacy timestamps or coverage yield unknown, not fabricated values. Completed-position detail may display context via isolated child; canonical account/grouping/metrics/notes/CSV remain byte/semantically unchanged.

**MUST and acceptance:** (1) canonical import/validation: deterministic sample roundtrip, malformed/duplicates rejected; (2) UTC and strict facts: DST/offset/boundary tests plus future actual/forecast/previous/schedule/impact mutation invariance; (3) coverage and atomic persistence: complete/partial/unknown distinguished, failed replace/reload/recovery retain valid state; (4) filters and indexed query: eligible-only results, no full-history scan per cursor; (5) panel/markers: actual browser selection, timeframe/prepend/resize/remount without lifecycle duplication or interference; (6) navigation: exact manual-step account/chart equivalence, cancellation/same-time/out-of-range/chunk behavior; (7) reproducible windows/context: exact half-open boundaries, overlap preservation and no account writes; (8) Phase 14 integration: all financial/grouping/export/reset contracts unchanged; (9) full regression, measured 10k/100k synthetic indexing/query/availability/render performance, bundle/build/lint/browser/diff/Git checkpoint per existing workflow. No invented CI timing thresholds. Anti-look-ahead failure blocks release.

**SHOULD:** provider-specific importers, CSV input, extra presets, research metadata export, simple event/category descriptive statistics, richer cluster UX. **DEFER:** provider selection commitment, third-party data acquisition/bundling without rights, live/API/cloud ingestion, backend/login/sync, AI/sentiment, advanced statistical engines, trade-schema changes, Phase 14 CSV changes, final UI design, replay/execution semantic changes, Phase 16 work. No remaining provider/ten-year-data decision blocks synthetic/canonical foundation implementation. Separate explicit human implementation authorization is the remaining authorization gate.

<details>
<summary>Superseded Phase 18.7 draft — historical only</summary>

Historical planning below may describe the earlier two-dimension model; treat conflicting portions as superseded and do not implement them.

The earlier trading UX draft described **two independent dimensions** and must not collapse them into one concept.

**Trading Mode**
1. **Free Mode** — discretionary backtesting. Supported actions may be used freely and are still recorded for later analysis.
2. **Protocol Mode** — trading is governed by the active Strategy Rules / Lab Protocol. Each governed action eventually resolves through one of:
   - `ALLOW`
   - `BLOCK`
   - `TRACK_VIOLATION`

**Order Method**
1. **Quick Trade** — BUY/SELL first, immediate/appropriate order creation, then supported SL/TP and position-management actions. Its purpose is fast execution with minimal interaction.
2. **Planned Trade** — evolution of the existing Long/Short Position workflow: define Entry + SL + TP on chart, choose/derive risk per trade, calculate position size and RR, review, then explicitly Place Order.

Required matrix:

| Trading mode | Quick Trade | Planned Trade |
| --- | --- | --- |
| Free | Fast BUY/SELL; supported SL/TP/intervention may follow | Entry/SL/TP → risk → size/RR → Place Order; later supported intervention remains available |
| Protocol | Available only when protocol permits the required action/risk model | Primary research workflow; locked protocol values and action policies govern the plan and subsequent position |

Architecture contract:
- Free/Protocol are **not separate execution engines**.
- Quick/Planned are **not separate execution engines**.
- Both order methods must converge to the same canonical Order Request → Rules validation → Execution Engine path.
- UI hiding/disabling is never the enforcement boundary; engine/domain validation must reject forbidden actions.
- Protocol restrictions must explain why an action is unavailable rather than silently removing capability.
- A `TRACK_VIOLATION` action remains executable but must be recorded with enough provenance for later compliant-vs-violation analysis.
- Do not invent a third order workflow without an explicit roadmap decision.

Protocol-governable actions/parameters should be designed to accommodate at least: setup/inclusion/exclusion context, entry, SL, TP, fixed or constrained RR, risk per trade, session, maximum orders, early close, partial close, move SL, move TP, cancel order and intervention policy. Full rule-engine enforcement belongs to the later strategy/research architecture and is not implied by this UX phase.

- Logika trading ada di JavaScript frontend, padahal seharusnya di engine backend.
- Tombol PREVIOUS tidak membatalkan trade yang sudah tertutup, hasil bisa tidak konsisten.
- Slippage pada TP dikurangkan dengan cara yang sama seperti pada SL; perlu ditinjau ulang.
- Belum ada tes otomatis.

**Yang bisa dipakai ulang:** rumus lot dari risiko, konsep mode eksekusi SL-first/TP-first,
gaya tampilan (Poppins), susunan panel statistik dan riwayat.

## Fase 2 — Order dan eksekusi
Market order, limit/stop, SL/TP dengan kebijakan intrabar yang terdokumentasi, spread,
slippage, komisi, position sizing (engine backend + tes).

**Kemajuan awal:** engine market order backend sudah dibuat dan dites: BUY/SELL, ukuran posisi
dari risiko, spread/slippage/komisi, SL/TP, gap melewati SL, penutupan manual, dan reset.
Jika satu candle menyentuh SL dan TP, SL diproses lebih dulu. Harga OHLC dianggap harga tengah;
jarak SL/TP dihitung dari harga entry aktual. Pengaturan akun default: saldo 10.000, kontrak
100 unit, biaya 0; semua nilai dapat diatur saat memulai replay. Frontend kini memiliki panel
BUY/SELL, risiko dan jarak SL/TP, penutupan manual, riwayat trade, serta marker entry/exit dan
garis harga posisi. Pending order dapat dibatalkan, pemicunya hanya diperiksa saat replay
maju, dan pengisian yang langsung menyentuh SL/TP mengikuti kebijakan SL-first. Analytics kini
menampilkan equity realized dari trade tertutup; floating P&L dan equity akun live masih perlu dibuat.

**Chart:** chart memakai TradingView Lightweight Charts (Apache-2.0). Overlay SMA 20, EMA 20,
dan EMA 50 dapat dinyalakan atau dimatikan langsung pada chart. Indikator dihitung dari candle
yang sudah terlihat di replay agar tidak membaca data masa depan. Tersedia garis harga sekali
klik, trendline dua titik, hapus garis gambar, serta pemilihan harga pending order dari chart
untuk dikonfirmasi di panel trading. Fitur berikutnya: RSI/volume dan pengelolaan order penuh
langsung dari chart.

**Position tool workflow:** Cursor, Long Position, dan Short Position tersedia. Klik chart untuk
membuat proyeksi posisi; Entry, stop, dan target dapat disesuaikan dengan handle. Proyeksi ini
hanya gambar rencana dan tidak mengirim order. Tiket order tetap dikonfirmasi secara terpisah.

**Chart UX — Phase 1 Shell:** top bar, left vertical tool groups, area chart utama, panel kanan,
dan kontrol replay bawah mulai dipisahkan. Dropdown timeframe pada shell hanya demo tampilan;
dataset candle tetap memakai timeframe saat impor. Interaction drawing yang lebih lengkap
menyusul di fase berikutnya.

## Asumsi yang berlaku sekarang
- Semua waktu disimpan dalam UTC. Timestamp CSV tanpa offset dianggap berada di zona waktu yang dipilih saat impor.
- Gap data (akhir pekan, libur) hanya peringatan; data dengan error ditolak seluruhnya.
- Replay default mulai di candle ke-101 supaya ada riwayat 100 candle di belakang titik mulai.
- Previous hanya menggeser tampilan; kemajuan baru dilacak oleh `high_water`.

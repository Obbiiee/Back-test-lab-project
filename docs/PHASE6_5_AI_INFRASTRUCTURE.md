Infrastructure only: no application source, trading/replay/data/legacy code or product functionality changed. Phase 7 is not authorized.

Tracked infrastructure: eight concise documents in `AI_CONTEXT/`, `frontend/scripts/ai-bundle.config.json`, `frontend/scripts/ai-bundle.mjs`, `frontend/tests/ai-bundle.test.mjs`; scripts added to `frontend/package.json`; root `/AI_BUNDLE/` ignored in `.gitignore`.

Run from `frontend/`: `npm run ai:bundle`, then `npm run ai:bundle:verify`. Regenerate before assigning a narrow task. Current task explicitly awaits Phase 7 instruction. Generator uses Node built-ins, an explicit four-category allowlist, deterministic ordering, byte-level SHA-256 and no volatile timestamps.

Output consists of README, combined CONTEXT, CURRENT_TASK, FILE_MANIFEST and copies under `files/<master-path>`. Manifest version 1 records config path/hash and each source path, bundle path, category, SHA-256 and byte length. Verifier compares freshly derived master/config manifest and every expected generated/copy byte; changed master/config is stale, edited bundle content requires review. Verification never writes. No automatic patch application exists.

All selected inputs are validated/read before replacement. Paths must be repository-relative files without traversal/backslashes/absolute paths or symlinks. Existing output must be the fixed direct child AI_BUNDLE and carry the generated marker; unrelated directories are refused. Regeneration intentionally replaces edits in generated output, so preserve secondary patches separately before regenerating. Never use bundle as production source or an independent application. Missing inputs leave existing output intact; filesystem write failures can leave partial generated output, which verification rejects.

Bundle intentionally omits node_modules, build output, market datasets, screenshots, old evidence, archives, unrelated engines and documentation. Selected Phase 6 tests are reference source: their dependencies/legacy fixtures are omitted. Run them in master after reviewed integration, not inside this partial package.

Automated infrastructure tests verify all generated bytes across repeated builds, stale master detection, read-only verification, edited-copy rejection, missing-input safety, traversal rejection, refusing unrelated output and unchanged source bytes. Full existing build/lint/Phase 4/5/6/trading-separation/trading/drawing/market gates also run. Browser re-test is unnecessary for this documentation/tooling phase because no product runtime changed.

# Boundaries

Economic news is a separate `frontend/src/news/` domain. Frozen versioned facts feed EventIndex's availability timeline and bounded time-tree filter views. NewsRepository verifies hashes in a separate native IndexedDB namespace before atomic active/previous swaps. NewsMarkerAdapter uses an official series primitive without autoscale/trading-marker ownership. NewsNavigationController requests existing manual steps and waits for revision plus account settlement acknowledgement; it never writes replay/account state. Strict projections alone reach chart/navigation/research. A separately memoized trade-context child preserves financial calculation ownership. Contract/evidence: [news report](../docs/PHASE14_5_ECONOMIC_NEWS.md).

Market data loaders → replay/live candle aggregation → CandleChart (native Lightweight Charts). Replay reveals market data; it does not own drawings.

Independent domains:
- Trading: simulator/useTrading, RiskReward controller/layer, native chart annotations. Owns orders, positions and entry/SL/TP.
- Trading analysis: backtestAnalysis is a pure read-only projection of canonical account exit records/active positions/balances. PositionsPanel memoizes on those inputs, never the replay cursor; BacktestAnalysis owns transient detail selection and a separate SVG balance curve. backtestExport serializes raw/grouped data without writing account state. replayResetGuard and ReplayResetConfirmation gate the existing workspace start/exit actions before any replay/account operation. No new store or persistence schema. Detailed contracts: [checkpoint](../docs/PHASE14_TRADING_UX_BACKTEST_ANALYSIS.md).
- Drawing: canonical model → DrawingManager/Registry → creation/interaction controllers → official Series Primitive views/renderers. React hook connects lifecycle and low-frequency state to chart.
- Indicators: legacy custom runtime stays retired. Chart-visible candles → IndicatorEngine → trusted pure spec calculation → normalized TIME + VALUE output → IndicatorSeriesAdapter (official Lightweight Charts line/histogram series). No imports from trading, drawing or market; no market/replay mutation APIs.

Canonical geometry is TIME + PRICE. Pixels are transient projection/interaction data. Selection, hover and drag are runtime state, never canonical serialized fields. Missing exact timestamps use deterministic interpolation/extrapolation between actual chart coordinates; body drag applies equal calendar-time and price deltas. Trading and Drawing stay separate. Persistence must not silently mutate geometry. `chart/LegacyObjectPersistence.js` protects old mixed records/backups while the trading compatibility bridge owns Risk/Reward objects.

DrawingManager committed snapshots → DrawingHistory (100 runtime actions) and DrawingPersistence → version-1 localStorage. Current single XAUUSD workspace uses `main:XAUUSD`, shared across timeframes and live/historical/replay modes; cursor and timeframe never partition storage. Restore validates through registry/models and rebuilds primitives. Pointer movement previews only; release commits once. Unsupported storage stays read-only, preserving original bytes. Lock blocks geometry but allows selection/deletion; hidden objects neither render nor hit-test.

Directory ownership: `frontend/src/` is the sole active implementation (reachable ownership is checked by test:repository; two intentional compatibility exports remain). `frontend/tests/` owns regressions and browser harnesses; `frontend/scripts/` owns infrastructure/data downloads. `frontend/legacy/phase3/` supplies historical geometry fixtures; root `legacy/` supplies historical snapshots. Standalone `backend/` and sample `data/` are not part of the workspace runtime. `docs/` preserves checkpoint reports/fixtures; new disposable evidence belongs in ignored `docs/_generated/` or `frontend/tests/artifacts/`. AI_BUNDLE is generated and ignored.

Core tools extend the same registry, creation controller and official series primitive. Horizontal/Vertical Lines store one TIME + PRICE anchor and drag only their price/time axis respectively. Rectangle stores exactly two anchors; four corners are derived for rendering/hit-testing/resize. A shared projectGeometry function keeps rendering and hit-testing aligned; no annotation supplies autoscaleInfo. The v1 persistence adapter and history/manager need no schema changes.

Advanced tools use the same immutable model factory, creation workflow, renderer and hit-testing. Fib stores only A/B; levels are derived (0 at B, 1 at A). Arrowhead is transient. Measure derives signed price/percentage/elapsed seconds and fractional bar distance using existing timestamp-to-logical interpolation; bar distance varies with the chart timeframe. Text adds only a validated text field to its v1 record and a transient React editor; DrawingManager.setText respects locks and commits once. No trading APIs are used by these tools.

IndicatorRegistry owns trusted specifications (type, legacy single or named multiple line/histogram outputs, warmup, scalar parameter defaults/validators and calculate function). Canonical instances contain only id/type/parameters/visible. IndicatorEngine keeps derived output and errors outside configs, validates changes before mutation and isolates calculation/series-update failures per instance, clearing stale series. Input copies contain only revealed candle fields and are frozen; output must use unique revealed timestamps and finite values, normalized chronologically. Warmup yields an empty output. Reviewed future calculators must be causal and deterministic; this is not a sandbox for user code.

CandleChart feeds precisely the same candles used by the candlestick series, after validated candle synchronization; no raw future replay dataset is passed. Candlestick series uses official update only for a proven unchanged historical prefix plus latest-bucket replacement/append; full setData remains the fallback. Indicator Engine retains full recomputation/setData for every transition. Visibility retains the instance/series; removal/detach release owned series. Chart cleanup detaches before chart.remove; React StrictMode remount can reattach safely. Registry is supplied at mount; configs can change without chart recreation. Malformed React config updates are rejected while retaining previous valid instances, with an optional error callback. Native Volume/annotations/drawing/trading remain on existing paths. The catalog-neutral default registry stays empty; production supplies productionRegistry, composing the unchanged overlayRegistry with exactly RSI, MACD, ATR and STOCHASTIC pane specs. Each instance/output key owns one official series; all outputs validate before synchronization and any failure clears every owned output for that instance. Bollinger uses three line series: basis, upper and lower. Pure close calculators use inclusive SMA, SMA-seeded EMA and population-standard-deviation Bollinger windows. IndicatorControls owns transient editing; FigmaWorkspace holds runtime-only configs. No indicator or pane storage. Trusted placement defaults to price; pane specs own one dedicated pane per instance. The existing adapter uses official addPane(true), addSeries(..., pane.paneIndex()), setStretchFactor and removePane(current index); references use official createPriceLine/removePriceLine. Runtime pane handles derive current indexes after reindex; canonical configs remain id/type/parameters/visible. Removal releases reference lines and all owned series before removing the preserved empty pane. Hide retains an owned blank pane and hides its references; detach/remount recreates ownership. RSI/ATR use documented Wilder mean seeds; MACD reuses SMA-seeded EMA, Stochastic uses raw rolling %K and SMA %D. Range specs keep oscillators at 0–100. Narrow price-pane click/hover guards and clipped RiskReward SVG prevent cross-pane interactions. Tests own reference indicators and browser fixtures.

Replay transition hints contain only kind/revision/timeframe. Start/stop/prepend/rewind have explicit kinds; a forward hint is classified from actual revealed values into latest-bucket update or append. Viewport/timeframe identity forces chart replacement, including changed frame after a prior forward hint. Incrementing committed revision acknowledges steps without revealing future data. PlaybackScheduler requests at most one step and waits for revision acknowledgement before scheduling another timeout; speed changes, pause and cleanup cancel timer generations. useReplayPlayback connects this to committed React effects. Trading replaySettlement validates raw append against its previous revealed prefix and account cursor before settling only the suffix; other transitions use the original scan. The simulator and execution policy are unchanged. Prefix validation remains linear, not an O(1) trust shortcut.

AccountPersistence owns the existing paper-account localStorage key and lossless safety validation, separate from simulator/settlement and financial interpretation. workspacePreferences owns safe favorites reads; WorkspaceErrorBoundary owns root render recovery. News marker mapping uses exact binary time lookup over sorted revealed candles rather than rebuilding full-history sets; availability indexing retains a single global timeline sort. No engine/schema migration.

Post-v1 documentation audit: [Phase 18.5 architecture/reference audit](../docs/PHASE18_5_ARCHITECTURE_REFERENCE_AUDIT.md) maps actual source ownership, preservation decisions and future UX risks. The [Trading Method/Session contract](../docs/TRADING_METHOD_SESSION_SPEC.md) is normalized future product authority, not implemented Method/Session runtime or Protocol enforcement. Existing local v1 behavior and release acceptance remain unchanged.

UI design token ownership: frontend/src/workspace/designTokens.css; terminal presentation state/bounds live in usePanelResize, and PositionsPanel hides only its content while retaining a focusable separator. Existing chart ResizeObserver reacts to layout; no financial state or storage key is added. Tool chooser icons/help remain FigmaWorkspace presentation over existing dispatch. [UI specification](../docs/PHASE18_6_UI_UX_DESIGN_SYSTEM.md) owns visual guidance.

Future trading UX handoff is owned by the existing [Method/Session specification](../docs/TRADING_METHOD_SESSION_SPEC.md). Planner/request/validation/confirmation/execution/evidence remain distinct. Demo units and future production integration prerequisites are explicit; v1 runtime is unchanged.

Prototype boundary: `tradingUx/` is reachable only through explicit main-entry query selection and lazy PrototypeEntry. Its pure model reuses validateOrder read-only, its chart reuses official LWC and legacy overlay/resize geometry; no account/persistence/replay writers. usePanelResize adds an optional extra header reserve, default unchanged. Prototype sample IDs/events/zero-cost units are not a durable ledger or production instrument profile.

Future backend architecture contracts belong to the [existing system blueprint, Phase 19 planning handoff](../docs/PRODUCT_SYSTEM_ARCHITECTURE_BLUEPRINT.md#38-phase-19--backend-architecture-planning-handoff). Modular-monolith ports, confirmation/revision/dedup, passport/lineage/log and research-job boundaries are planned only. Standalone FastAPI remains unconnected; no frontend migration or execution-authority switch is implied.
